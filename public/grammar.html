Modern Jianpu Reloaded Grammar Reference

A concise reference for Modern Jianpu Reloaded source files, including headers, notes, durations, chords, ties, and tokenizer-level syntax.

Reference

1. File Structure

A source file contains an optional metadata header followed by score lines. Header mode starts when the parser sees an = separator anywhere in the file; all header properties must appear before that separator. Without a separator, the whole file is parsed as score text. Empty files are valid and use default header values. 

title: "Twinkle"
key: "C"
time: "4/4"
tempo: "120"
=
1 1 5 5 | 6 6 5 - |

2. Whitespace, Lines, And Comments

Spaces and tabs may appear between tokens and are ignored. Newlines separate header properties and score lines. Comments begin with ; and continue until the next line break; the line break itself still separates the surrounding syntax. 

1 2 3 4 ; this comment is ignored
5 6 7 1'

3. Header Properties

Header properties use name: "value". Names contain ASCII letters and underscores. Values are double-quoted strings on one line. A backslash skips the following character while tokenizing, but stored header values keep the raw inner text.

Built-in fields are title, subtitle, composer, key, time, tempo, and hidden. Unknown fields are preserved in header.raw but have no built-in behavior. Any non-empty hidden value hides rendered header metadata. 

title: "Song Title"
subtitle: "Optional subtitle"
composer: "Composer"
hidden: "yes"
=
1 2 3 4

4. Key, Time, And Tempo

Supported keys are C C# Db D D# Eb E F F# Gb G G# Ab A A# Bb B. One space inside the key value is ignored. Accidentals may also be written before the key letter, such as #C and bB. Invalid keys are parse errors.

Time signatures use beatsPerMeasure/beatsPerWholeNote. Numerators are 2 3 4 6 9 12; denominators are 2 4 8 16. Tempo must be a positive number. 

key: "D"
time: "6/8"
tempo: "96"

5. Score Lines And Measures

A score line may start with a label, followed by one or more measures. Labels use the same identifier form as header names and render at the left edge of the score line. Measures are separated by |. One leading bar and one trailing bar are accepted, but empty measures are errors. 

verse: | 1 2 3 4 | 5 6 7 1' |
1 2 || 3 4  ; invalid empty measure

6. Notes, Rests, Drums, And Octaves

Pitch notes are 1 through 7. Rest is 0. Drum note is uppercase X; lowercase x is not a drum note. Octave suffixes after pitch notes use ' to raise and , to lower. A measure may also begin with a repeated octave prefix, which applies to all pitch notes in that measure. 

1 2 3 4 5 6 7
0 X
1' 2'' 6, 5,,
'' 1 2 3 4

7. Accidentals

Accidentals appear before pitch notes: #, ##, b, bb, and %. They apply only to pitch notes. During playback/export and tie validation, an accidental affects later notes of the same scale degree in the current measure, then resets at the next bar. 

#4 b7 %4 ##1 bb6
#4 4 | 4

8. Durations

The default note duration is a quarter note. Dashes extend duration by quarter-note units. Slashes halve the duration. Dots add dotted rhythm. Dash durations and slash/dot durations cannot be mixed on the same note. 

1     = 1/4 whole note
1-    = 1/2 whole note
1--   = 3/4 whole note
1---  = 1 whole note
1/    = 1/8 whole note
1//   = 1/16 whole note
1.    = 3/8 whole note
1/.   = 3/16 whole note

9. Chords

Chords are enclosed in braces and contain pitch notes only. Rests, drums, empty chords, and duration suffixes inside the braces are invalid. The duration suffix follows the closing brace and applies to the whole chord. 

{1 3 5}
{#1 3 b5}/
{1' 3' 5'}-

10. Ties

A tie marker ~ appears before the tied note. The first note cannot be tied. A tied note must follow a sounding note and must match the previous sounding pitch, chord, or drum note after measure-local accidental persistence is applied. 

1 ~1
3 - ~3/
{1 3 5} ~{1 3 5}

11. Compact Notation

Whitespace between notes is optional when tokens remain unambiguous. Compact score text is useful for dense melodies, but invalid characters and stray duration suffixes are still reported at their source positions. 

1155|665-|
1/2/3/4/

12. Diagnostics And Semantic Checks

  • Header key, time, and tempo values are normalized and validated after raw header parsing.
  • Measure durations are compared with the time signature after parsing and reported as warnings.
  • Ties are validated after parsing, using measure-local accidental persistence.
  • Malformed compact notation, unmatched chord braces, empty chords, empty measures, and invalid tie targets are errors.

Parser Overview

Leading newlines are ignored, then an optional header and optional score are parsed before end of file. 

file ::= NEWLINE* header? score? EOF

Header

header   ::= property* EQUALS+ NEWLINE+
property ::= label STRING NEWLINE+
label    ::= IDENTIFIER ":"

Semantic header fields are title, subtitle, composer, key, time, tempo, and hidden. Unknown fields are preserved in header.raw.

Score

score ::= line (NEWLINE+ line)* NEWLINE*

Line

line  ::= label? BAR? measure (BAR measure)* BAR?
label ::= IDENTIFIER ":"

A single leading bar and a single trailing bar are accepted. Empty measures are still parse errors; for example, 1 2 || 3 4 creates an empty measure between the two bar tokens.

Measure

measure ::= octave? durable_note+
octave  ::= LOWER+ | HIGHER+

A measure octave prefix is consumed only at the start of the measure. It is one repeated token kind: ,+ or '+. Mixed prefixes are not one prefix.

Durable Note

durable_note ::= tie? general_note length?
tie          ::= TIE

Tie legality is validated after parsing. A leading ~ is syntactically accepted here, then rejected later if it is the first note, follows a rest, or does not match the previous sounding note.

General Note

general_note ::= chord | rest | drum
rest         ::= REST
drum         ::= DRUM

Pitch

pitch_note ::= accidental? NOTE octave?
accidental ::= SHARPSHARP | SHARP | FLATFLAT | FLAT | NATURAL
octave     ::= LOWER+ | HIGHER+

Chord

chord ::= pitch_note | "{" pitch_note+ "}"

Chords contain pitch notes only. Rests, drum notes, duration suffixes before }, and empty chords are invalid.

Duration

length ::= DASH+ | (HALF | DOT)+

Dash duration marks cannot be combined with slash or dot marks. The parser reports a specific duration error for forms such as 1-/ and 1/-.

Token Reference

The parser consumes whitespace and comments between grammar tokens, so they are listed separately from tokens that become part of the parsed structure. Reserved token spellings such as bb, b, and X are matched before identifiers. 

Ignored between tokens:
WS         ::= " " | "\t"
COMMENT    ::= ";" characters-until-newline

Structural tokens:
IDENTIFIER ::= /[A-Za-z_]+/ except bb, b, X
STRING     ::= '"' (escaped-char | non-newline-non-quote)* '"'
NOTE       ::= "1" | "2" | "3" | "4" | "5" | "6" | "7"
REST       ::= "0"
DRUM       ::= "X"
BAR        ::= "|"
SHARPSHARP ::= "##"
SHARP      ::= "#"
FLATFLAT   ::= "bb"
FLAT       ::= "b"
NATURAL    ::= "%"
HALF       ::= "/"
DOT        ::= "."
DASH       ::= "-"
LOWER      ::= ","
HIGHER     ::= "'"
TIE        ::= "~"
EQUALS     ::= "="
NEWLINE    ::= "\n" | "\r\n" | "\r"
EOF        ::= end-of-file
