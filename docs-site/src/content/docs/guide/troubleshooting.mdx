The syntax pages document warnings and errors next to the notation that causes them. Use this guide when you need a quick workflow for finding the source of a problem.

## Check the Whole File

Run validation from the CLI to see every diagnostic with source locations:

```sh
pnpm run cli -- validate path/to/score.jpu
```

In the browser app, use the diagnostics panel and jump from the reported line back to the source.

## Match the Diagnostic to a Syntax Page

- Header fields, unterminated strings, invalid `key`, invalid `time`, and invalid `tempo`: see [File Header](../../syntax/header/).
- Invalid note characters, lowercase drum notes, chord member errors, empty-chord warnings, and illegal ties: see [Notes and Rests](../../syntax/notes/).
- Mixed duration suffixes, stray duration suffixes, and short or long measures: see [Rhythm](../../syntax/rhythm/).
- Missing final endings or skipped ending passes: see [Repeats](../../syntax/repeats/).
- Lyric count warnings, lyrics before any score line, reserved `T10:`, and invalid track order: see [Lyrics and Tracks](../../syntax/lyrics-tracks/).

## Reduce the Example

If the fix is not obvious, copy the smallest section that still produces the diagnostic into a scratch score. Keep the header, the affected line, and any neighboring repeat, lyric, or track line that changes the meaning.

After the small case validates, apply the same edit back to the full score and run validation again.
