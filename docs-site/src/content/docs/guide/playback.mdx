## Playback Model

Notes, rests, accidentals, octave marks, chords, ties, repeat barlines, repeated endings, key signatures, tempo, and labeled tracks all affect the timed playback result.

The compiler first resolves the score structure into timed events. It then applies Program selection, track volume, note dynamics, and drum mapping before browser playback or audio/MIDI export receives the result.

Lyrics render visually but do not affect playback timing.

## Browser Playback

The browser app uses WebAudioTinySynth. Playback schedules notes incrementally, highlights active rendered notes, and stops when the source changes.

Click-to-play starts from rendered note metadata. If the clicked note is the first playback note and initial-rest omission is enabled, leading rests are skipped.

Rendered score previews in the documentation use the same playback compiler. When a preview includes playback controls, clicking a rendered note starts that preview from the clicked note.

## Programs And Drums

Programs `0..127` use melodic TinySynth programs. Programs `128..174` use drum mode. In drum mode, source `X` maps to percussion note `program - 128 + 35`.

Use `program` in the file header to set the score-level default Program. The browser and CLI Program controls are used only when the file header omits `program`.

Use `Tn.program` to assign a melodic Program to a labeled melodic track. It overrides `program` for that track. Melodic per-track numeric values are limited to `0..127`, and quoted names resolve through the same General MIDI Program list used by the browser selector.

Use `Pn.program` on percussion tracks such as `P1:` or `P2:` to assign a percussion Program in the `128..174` range. Each P track plays its own GM percussion sound and shares MIDI channel 10 with other P tracks, so multiple P tracks can form a drum kit in one score.

## Volumes And Dynamics

Use `volume` to set the score-level default track volume. Use `Tn.volume` or `Pn.volume` to override one labeled track from `0` to `2` or `0%` to `200%`.

Resolved track volume comes from the matching track override, then score-level `volume`, then `1`. It combines with the browser volume slider or CLI `--amplitude`, so master volume changes preserve the relative balance between tracks.

Per-note dynamic markings set note velocity before track volume is applied. Hairpins interpolate velocities between their endpoints; when an endpoint has an explicit dynamic marking, that marking becomes the interpolation target.

## Repeats And Tracks

Repeat barlines and repeated endings are expanded for playback and export. The rendered score still shows the written repeat syntax, while the playback model follows the expanded order.

Labeled tracks play together inside a voice group; the next group starts after the previous group ends. This lets multiple melodic or percussion tracks sound together without changing the written grouping rules.
