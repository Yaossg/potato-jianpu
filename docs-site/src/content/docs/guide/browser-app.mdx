Use the browser app when you want immediate feedback while writing a score. It keeps the source editor, diagnostics, preview, playback, examples, settings, and downloads in one local workspace, so it is the quickest way to try `.jpu` syntax before saving a file or moving the workflow to the CLI.

## Workspace

Use Open to load a local `.jpu` file into the editor. If the editor already contains text, the app asks before replacing it. Use Save to download the current source text as a `.jpu` file; saving source does not require the score to parse successfully.

The editor keeps a browser-local draft on the current device. Reloading the page restores that draft, while Save creates a file you can keep, share, or pass to the CLI later.

The clear action asks for confirmation before removing the current source.

## Local Drafts

The app stores its draft and display preferences in this browser on this device. It does not create an account or synchronize the draft to another browser or device. Clearing this site's browser data can remove the saved draft and preferences.

Drafts and preferences from Modern Jianpu Markup are restored automatically on the same site when no newer saved value exists. A different site address has separate browser storage; save a `.jpu` file on the old site and open it on the new site to transfer your score.

Use Save to keep a `.jpu` file outside the browser. Saving a file is the right way to back up a score, move it to another device, share it, or use it with the CLI.

## Editing And Diagnostics

The source editor accepts the same `.jpu` text that the CLI reads. It shows line numbers, highlights the current line, and can wrap or preserve long source lines depending on the editor setting.

Diagnostics appear below the editor, are highlighted in the source, and add red or yellow markers beside affected line numbers. Click a diagnostic or gutter marker to focus the affected range. Errors prevent a fresh render, but the preview keeps the last valid score visible with a stale-preview notice so you can compare while fixing the source. Warnings keep the score usable and mark behavior that deserves review, such as measure-duration mismatches.

## Preview And Playback

First use shows the sound-bank download progress, followed by audio preparation. If the download size is unavailable, the app shows downloaded MB without a percentage. Stopping playback dismisses its progress indicator; the download continues for reuse. If loading fails, try playback or export again.

When browser storage is available, the downloaded bank is saved across reloads and shared by the app and documentation on the same site. Cached use skips the download indicator. Editing scores, switching instruments, and ordinary app updates do not invalidate it; changing the bank version requires a new download. Clearing site data, browser storage eviction, or leaving a private session can remove it. A different site address or browser profile has separate storage. This saves the sound bank for offline reuse; opening the app itself offline still depends on its page and audio engine being available.

The preview updates from the same parser and renderer used by the CLI, so syntax behavior stays shared across browser and terminal workflows. The preview summary shows how many score lines are rendered, the active page width, and whether that width came from the panel, content inference, a manual setting, or a paper preset.

Use the playback button to audition the current score. Active notes are highlighted in the rendered preview as playback advances. You can also click a rendered note to start playback from that note. Changing source, loading an example, or stopping playback clears the active highlight.

Playback in the browser uses the shared timing and sound model used by MIDI, WAV, and MP3 export. For Program, drum, volume, dynamics, repeat, and track behavior, use the Playback guide as the reference.

## Examples

The examples panel loads bundled `.jpu` scores into the editor. If the editor already contains text, the app asks before replacing it. Loading an example stops playback and closes the panel, then the loaded source is handled like any other editable draft.

Examples are useful as editable starting points: load one, change the source, then use diagnostics and preview feedback to learn how the syntax behaves.

## Page Layout And Settings

Page settings control visual preview and visual downloads: paper preset, orientation, width mode, page size, page margin, page numbers, measure numbers, notation color, background, and justification. Header fields such as `paginate`, `measureNumbers`, and `footer` can also provide visual-output defaults for a score.

Justification changes visual spacing only; it does not change the `.jpu` source, playback timing, or MIDI and audio output. Choose None to keep natural measure spacing, Except last line to expand every visual score line except the final one, or All lines to expand every visual score line. The selected mode is used by the preview and visual downloads.

Choose a paper preset and orientation when the output should fit A4, B5, or Letter paper. Use custom width and height only when a target needs a specific page size. Pagination turns the preview and visual downloads into fixed-height pages; page margin, page numbers, and header-provided footer text then reserve space inside each page.

Editor settings control source editing preferences: line wrapping, editor font size, line numbers, current-line highlight, and inline diagnostic highlights.

Sound settings control browser playback and browser-rendered audio downloads: default Program, master volume, initial-rest omission, and audition. Export settings control PNG scale and pixel dimensions, split-page SVG/PNG downloads, and the audio sample rate used for WAV and MP3 rendering. PNG defaults to `2x`, uses bundled export fonts, and always downloads with an opaque background.

The language and theme buttons are in the top toolbar. Language preference, theme preference, source text, editor display preferences, and editor/preview split width are stored locally in the browser.

## Downloads

The export menu downloads the current valid score as SVG, PNG, PDF, MIDI, WAV, or MP3. SVG, PNG, and PDF use the current page settings. MIDI, WAV, and MP3 use the shared playback model and the current sound settings where applicable.

SVG, PNG, and PDF downloads omit playback highlighting even when the score is playing. If an export font fails to download, retry the export after the connection recovers. WAV and MP3 use the same full `0–200%` master volume range as preview playback, including mute.

Enable Paginate in Page Settings when you want the preview and visual downloads to use fixed-height pages. Enable Split pages in Export Settings when SVG or PNG should download one file per rendered page.

Audio export can take longer than image or MIDI export because the browser renders the full arrangement before downloading. While WAV or MP3 is rendering, the export menu reports the event count and approximate duration.

Choose **Video (Experimental)** in the export menu to set video dimensions, frame rate, quality, file format, and note highlighting for a score video with audio. Cancel is available beside the progress indicator. See the [Export guide](../export/).

## Help

The GitHub button in the toolbar opens the project's source repository in a new tab, keeping the editor open.

The help button opens the localized documentation home: `/docs/` in English and `/docs/zh/` in Simplified Chinese. From there, use the syntax pages for notation rules, the CLI guide for repeatable terminal workflows, the Playback guide for timing and sound behavior, and the Export guide for format-specific output behavior.
