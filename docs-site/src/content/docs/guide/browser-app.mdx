Use the browser app when you want immediate feedback while writing a score. The app keeps editing, validation, preview, playback, and export in one local workspace, so it is the fastest place to try syntax before saving or scripting a `.jpu` file elsewhere.

## Editing And Diagnostics

The source editor accepts the same `.jpu` text that the CLI reads. It shows line numbers, highlights the current line, and can wrap or preserve long source lines depending on the editor setting. Source text is stored in browser local storage, so reloading the page keeps the draft on the same device.

Diagnostics appear below the editor, are highlighted in the source, and add red or yellow markers beside affected line numbers. Click a diagnostic or gutter marker to focus the affected range. Errors prevent a fresh render, but the preview keeps the last valid score visible with a stale-preview notice so you can compare while fixing the source. Warnings keep the score usable and mark behavior that deserves review, such as measure-duration mismatches.

The clear action asks for confirmation before removing the current source.

## Preview And Playback

The preview updates from the same parser and renderer used by the CLI, so syntax behavior stays shared across browser and terminal workflows. The preview summary shows how many score lines are rendered, the active page width, and whether that width came from the panel, content inference, or a manual setting.

Use the playback button to audition the current score. Active notes are highlighted in the rendered preview as playback advances. You can also click a rendered note to start playback from that note. Changing source, loading an example, or stopping playback clears the active highlight.

Playback uses the shared arrangement compiler, so notes, rests, chords, ties, repeats, repeated endings, labeled tracks, key signatures, per-track melodic Programs, and drum programs follow the same timing rules used by MIDI, WAV, and MP3 export.

## Examples

The examples panel loads bundled `.jpu` scores into the editor. If the editor already contains text, the app asks before replacing it. Loading an example stops playback and closes the panel, then the loaded source is handled like any other editable draft.

## Export

The export menu downloads the current valid score as SVG, PNG, MIDI, WAV, or MP3. SVG and PNG use the current page settings: width, color, background, and justification. MIDI uses the selected default Program, any score-level `Tn.program` headers, and the initial-rest setting. WAV and MP3 are rendered locally in the browser with the same Program resolution, volume, sample rate, and initial-rest setting.

Audio export can take longer than image or MIDI export because the browser renders the full arrangement before downloading. While WAV or MP3 is rendering, the export menu reports the event count and approximate duration.

## Settings

Page settings control visual output:

- Width mode: match the preview panel, infer width from score content, or use a manual pixel width.
- Color and page: set notation color and SVG/PNG background.
- Justify: leave natural spacing, justify all but the last line, or justify every line.

Editor settings currently include source wrapping.

Sound settings control playback and audio export:

- Program: choose the default General MIDI program or drum-note program for tracks without `Tn.program`.
- Volume: adjust browser playback and browser-rendered WAV/MP3 output.
- Audio sample rate: choose the WAV/MP3 render sample rate.
- Omit initial rests: skip shared leading silence when starting from the beginning.
- Audition: play a short phrase with the selected sound.

The language and theme buttons are in the top toolbar. Language preference, theme preference, source text, and source-wrap preference are stored locally in the browser.

## Help

The help button opens the localized documentation home: `/docs/` in English and `/docs/zh/` in Simplified Chinese. From there, use the syntax pages for notation rules, the CLI guide for warnings and errors, and the export guide for format-specific behavior.
