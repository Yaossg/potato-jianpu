一个文档可以包含可选的文件头，后面再接可选的乐谱正文。只有文件里出现由一个或多个 `=` 组成的分隔行时，解析器才会识别文件头。文件头字段必须写在分隔行之前；乐谱、歌词和轨道行写在它之后。没有分隔行时，整个文件都会按乐谱正文解析。

```jpu valid
title: "Example"
composer: "Traditional"
time: "4/4"
=
1 2 3 4 | 5 - 5 -
```

解析器把有空格和无空格的写法视为同一套语法。下面两个乐谱主体等价：

```jpu valid
1234|5-5-
```

```jpu valid
1 2 3 4 | 5 - 5 -
```

注释从 `;` 开始，到当前行末结束。

```jpu valid
1 2 3 4 | ; a comment
5 - 5 -
```

空行和开头的换行会被忽略。一个文档可以只有乐谱主体，也可以只有“文件头加分隔行”而没有乐谱正文，甚至可以为空。只有乐谱主体时不需要分隔行。

```jpu valid
1 2 3 4 | 5 - 5 -
```

小节用 <SyntaxToken token="|" label="小节线" /> 分隔。行首可以单独写小节线或反复开始，行尾也可以单独写小节线或反复结束。连续小节线之间的空小节会产生警告并被忽略，不会变成实际发声内容。

```jpu warning
1 2 || 3 4
```

换行是有意义的，因为它会分隔文件头字段、乐谱行和歌词行。连续空行会被折叠，所以两行乐谱之间的空行不会生成额外的渲染行。

```jpu valid
1 2 3 4

5 6 7 1'
```
