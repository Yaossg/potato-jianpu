需要可重复检查、源码检查和脚本化导出时，使用 CLI。它读取和浏览器 App 相同的 `.jpu` 文件，并使用同一套解析器、渲染器、播放模型和导出路径。

## 快速开始

```sh
pnpm run cli -- --version
pnpm run cli -- validate examples/twinkle.jpu
pnpm run cli -- parse examples/twinkle.jpu
```

从仓库根目录运行命令。开发时，`pnpm run cli --` 会把后续参数传给 Modern Jianpu Markup CLI。

## 校验与检查

`validate` 会报告诊断而不写出文件。当你只需要知道乐谱是否能干净解析时，可以在脚本里或提交 `.jpu` 文件前使用它。

`parse` 会打印解析后的文档数据，方便在渲染或导出前确认文件头字段、谱面行、带标签轨道、歌词、反复或记谱 token 是如何被解释的。

诊断使用和浏览器 App 相同的解析器行为。错误会停止导出命令；警告不会阻止使用乐谱，但表示需要确认的行为。

## 视觉导出命令

```sh
pnpm run cli -- export-svg examples/twinkle.jpu -o twinkle.svg
pnpm run cli -- export-png examples/twinkle.jpu -o twinkle.png
pnpm run cli -- export-pdf examples/twinkle.jpu -o twinkle.pdf
```

SVG、PNG 和 PDF 导出支持 `--paper <a4|b5|letter>`、`--orientation <portrait|landscape>`、`--page-width <px>`、`--page-height <px>`、`--page-margin <px>`、`--page-footer <text>`、`--page-numbers`、`--paginate`、`--color <css>` 和 `--background <css>`。显式页面宽度和页面高度会覆盖纸张预设尺寸。

SVG 和 PNG 导出还支持 `--split-pages`。使用 `-o score.svg` 时，拆页输出会写出 `score-01.svg`、`score-02.svg` 等文件，并且不会覆盖已有分页文件。

## MIDI 与音频导出命令

```sh
pnpm run cli -- export-midi examples/twinkle.jpu -o twinkle.mid
pnpm run cli -- export-wav examples/twinkle.jpu -o twinkle.wav
pnpm run cli -- export-mp3 examples/twinkle.jpu -o twinkle.mp3
```

MIDI、WAV 和 MP3 导出支持 `--program <number>` 和 `--omit-initial-rest`。WAV 和 MP3 还支持 `--sample-rate <hz>` 与 `--amplitude <0-1>`。MP3 另外支持 `--bit-rate <kbps>`。

`--program` 只是 fallback 默认 Program。文件头里的 `program`、`Tn.program` 和 `Pn.program` 字段可以为乐谱或单独轨道覆盖它。Program、鼓音、音量、力度和反复行为见“播放”指南。

## 脚本化说明

当同一份乐谱需要反复检查或导出时，使用 CLI。常见流程是先运行 `validate`，诊断通过后再运行一个或多个导出命令。

把格式相关选择放在对应导出命令旁边：视觉命令携带页面和颜色选项，MIDI/音频命令携带 Program 和音频渲染选项。完整输出行为以“导出”指南为准。
