语法页面会把警告和错误放在触发它们的记谱规则旁边说明。需要快速定位问题来源时，可以按这个流程排查。

## 检查整个文件

使用 CLI 校验文件，可以看到带源码位置的完整诊断：

```sh
pnpm run cli -- validate path/to/score.jpu
```

在浏览器 App 中，可以使用诊断面板，再从报告的行号回到源码位置。

## 把诊断对应到语法页面

- 文件头字段、未结束字符串、无效 `key`、无效 `time`、无效 `tempo`：见 [文件头](../../syntax/header/)。
- 无效音符字符、小写鼓音、和弦成员错误、空和弦警告、非法延音线：见 [音符与休止符](../../syntax/notes/)。
- 混用时值后缀、游离时值后缀、小节过短或过长：见 [节奏](../../syntax/rhythm/)。
- 缺少最终反复结尾或跳过结尾编号：见 [反复](../../syntax/repeats/)。
- 歌词数量警告、歌词出现在任何乐谱行之前、保留的 `T10:`、无效轨道顺序：见 [歌词与多轨](../../syntax/lyrics-tracks/)。

## 缩小例子

如果修法不明显，可以把仍然触发诊断的最小片段复制到临时乐谱里。保留文件头、受影响的行，以及会改变含义的相邻反复、歌词或轨道行。

小例子通过校验后，再把同样的修改应用回完整乐谱，并重新运行校验。
