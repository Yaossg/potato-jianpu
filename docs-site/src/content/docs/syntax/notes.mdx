## Basic Notes

Numbered notes use `1` through `7`. Use `0` for a rest and `X` for a drum note.

<JianpuSource
  title="Basic note source"
  source={`1 2 3 4 | 5 6 7 0 | X X X X`}
/>

<ScorePreview title="Basic notes, rest, and drums" source={`1 2 3 4 | 5 6 7 0 | X X X X`} />

Lowercase `x` is not a drum note.

<JianpuExample
  title="Invalid drum spelling"
  status="invalid"
  description="Drum notes use uppercase X only."
  source={`1 2 x 4`}
/>

## Accidentals and Octaves

Accidentals come before a pitch note. `#` and `##` raise a pitch, `b` and `bb` lower it, and `%` cancels the active accidental for that note spelling.

<JianpuSource title="Accidental source" source={`#1 b2 %3 ##4 | bb5 - - -`} />

<ScorePreview source={`#1 b2 %3 ##4 | bb5 - - -`} />

Accidentals apply only to pitch notes. They persist within the current measure for playback, export, and tie validation, then reset at the next measure boundary.

Octave suffixes come after a note. A dot above or below the note changes the octave.

<JianpuSource title="Octave suffix source" source={`1' 2'' 3, 4,,`} />

<ScorePreview source={`1' 2'' 3, 4,,`} />

Each `'` raises the note by one octave; each `,` lowers it by one octave. Measure-level octave prefixes can also shift all pitch notes at the start of a measure. Per-note suffixes add to that measure prefix.

<JianpuSource
  title="Measure octave prefix source"
  source={`time: 3/4
===
' 1 2 3 | , 1 2 3`}
/>

<ScorePreview
  source={`time: 3/4
===
' 1 2 3 | , 1 2 3`}
/>

The prefix must appear before notes in the measure. Mixed prefix characters are not one prefix.

## Chords

Chords are written with braces.

<JianpuSource
  title="Chord source"
  source={`{1 3 5} - {2 4 6} -`}
/>

<ScorePreview title="Rendered chords" source={`{1 3 5} - {2 4 6} -`} />

Chord members can use accidentals and octave suffixes. Rests and drum notes are not valid chord members. Put the duration suffix after the closing brace to apply it to the whole chord.

<JianpuSource title="Chord member source" source={`{#1 3 b5}/ {1' 3' 5'}- 0/ 0`} />

<ScorePreview source={`{#1 3 b5}/ {1' 3' 5'}- 0/ 0`} />

<JianpuExample
  title="Empty chord"
  status="warning"
  description="An empty chord is accepted, rendered as a rest, and reported as a warning."
  source={`1 {} 3 4`}
/>

<JianpuExample
  title="Invalid chord member"
  status="invalid"
  description="Chord members must be pitch notes, so rests and drums are rejected inside braces."
  source={`{1 0 X}`}
/>

A leading tie marker `~` ties a note to the previous compatible note.

## Ties

<JianpuSource
  title="Tie source"
  source={`1 - - - | ~1 - - -`}
/>

<ScorePreview title="Rendered tie" source={`1 - - - | ~1 - - -`} />

The tie target must be compatible with the previous sounding pitch. A tied note cannot be the first note in a track, and ties are validated independently for labeled tracks.

<JianpuSource
  title="Compatible tie source"
  source={`time: 2/4
===
#4 ~4 | X ~X | {1 3 5} ~{1 3 5}`}
/>

<ScorePreview
  source={`time: 2/4
===
#4 ~4 | X ~X | {1 3 5} ~{1 3 5}`}
/>

<JianpuExample
  title="Illegal tie"
  status="invalid"
  description="A tie cannot start a track, follow a rest, or change pitch target."
  source={`1 0 ~1`}
/>

## Dynamics (Velocity)

Per-note dynamics use Italian dynamic markings as a prefix before the note. A dynamic applies to exactly one note. Spaces between the marking and the note are optional.

<JianpuSource
  title="Dynamic marking source"
  source={`time: 2/4
===
f1 p2 | mf3 ff4`}
/>

<ScorePreview title="Rendered dynamics" source={`time: 2/4
===
f1 p2 | mf3 ff4`} />

Eight dynamic levels are supported, each mapped to a MIDI velocity value:

| Marking | Meaning | MIDI velocity |
| --- | --- | --- |
| `ppp` | pianississimo | 16 |
| `pp` | pianissimo | 33 |
| `p` | piano | 49 |
| `mp` | mezzo-piano | 61 |
| `mf` | mezzo-forte | 73 |
| `f` | forte | 85 |
| `ff` | fortissimo | 102 |
| `fff` | fortississimo | 118 |

Dynamics can also be applied to chords, rests, and tied notes.

<JianpuSource
  title="Dynamics with chords, rests, and ties"
  source={`time: 2/4
===
mf {1 3 5} - | f1 ~f1 | p0 -`}
/>

<ScorePreview
  source={`time: 2/4
===
mf {1 3 5} - | f1 ~f1 | p0 -`}
/>

Gradual dynamics use paired hairpin markers before durable notes. Write `<` at
both endpoints for crescendo and `>` at both endpoints for diminuendo. The
first marker starts the hairpin, and the matching marker later in the same
track ends it.

<JianpuSource
  title="Hairpin dynamic source"
  source={`time: 2/4
===
p < 1 2
3 f < 4`}
/>

<ScorePreview
  title="Rendered hairpin dynamics"
  source={`time: 2/4
===
p < 1 2
3 f < 4`}
/>

Opposite hairpins can meet on one note: `<>` ends a crescendo and starts a
diminuendo on that note, while `><` does the reverse. Hairpins may cross source
lines and visual wraps; the renderer draws a separate hairpin segment on each
visual line. If both endpoints have explicit dynamics, the parser warns when
the hairpin direction disagrees with the written dynamics.

<JianpuExample
  title="Hairpin direction warning"
  status="warning"
  description="A crescendo should end louder than it starts."
  source={`time: 3/4
===
f < 1 2 p < 3`}
/>

<JianpuExample
  title="Tie before dynamic"
  status="invalid"
  description="The dynamic marker must come after the tie prefix: write ~f1, not f~1."
  source={`1 f~1`}
/>

When no per-note dynamic or hairpin endpoint is written, the track-level or score-level volume from the header controls the velocity.
