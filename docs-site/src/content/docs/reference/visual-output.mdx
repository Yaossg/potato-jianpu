Use this reference when a score looks different after changing paper, margins, pagination, or export format. It describes visible output behavior for the browser preview, browser downloads, and CLI visual exports.

## Shared Rendering Model

SVG, PNG, and PDF begin with the same score layout. The browser preview uses that layout too, so page width, paper preset, orientation, pagination, margin, notation color, background, footer, page numbers, and justification affect visual output together.

The file header can set `paginate`, `footer`, and `numbering` defaults. A CLI option or the browser's current Page Settings can choose a different result for that export without changing the `.jpu` source.

## Page Size And Source Lines

`pageWidth` is both the SVG viewport width and the maximum width available to a rendered score group. A paper preset resolves width and height together: A4 is `1190 × 1684`, B5 is `998 × 1418`, and Letter is `1224 × 1584` in renderer units. Portrait and landscape swap the preset dimensions; an explicit width or height overrides that dimension after the preset is resolved.

Page margin applies equally on all four sides. It reduces the content box used for header layout, score scaling, justification, and pagination, but it does not shrink the exported SVG or PDF page itself.

Every source score line stays one rendered line; page width never inserts measure-level line breaks. If a complete score group is wider than the content box, it is horizontally scaled to fit. Simultaneous tracks share one scale, and aligned lyric syllables follow the same scale so their note positions remain synchronized. An ordinary lyric does not inherit music scaling; it stays at normal scale unless its own full line is overwide, in which case that lyric line is independently scaled. Horizontal scaling does not reduce font height, vertical spacing, or line height.

Justification changes only horizontal visual spacing:

- None keeps natural measure spacing.
- Except last line stretches every visual score line except the final one.
- All lines stretches every visual score line.

It does not change `.jpu` source, playback timing, MIDI, WAV, or MP3 output.

## Pagination And Adornments

Without pagination, visual output is one adaptive-height page. With pagination, the renderer creates fixed-height pages, keeps the score header on the first page only, and draws visible page boundaries. A simultaneous track group and its lyrics move as one indivisible block. If one block is taller than a page's usable area, it starts at the top of a new page without vertical scaling and produces a layout warning. `---` on a line by itself is a manual page break: it moves the next score group to a new page only when pagination is enabled.

Page footer text is drawn at the bottom-left of every page. Page numbers are centered and use `current / total`. Both reserve vertical space, so score content does not overlap them. Supplying a page height alone does not enable pagination; enable Paginate in the browser or pass `--paginate` to the CLI.

## Format Results

| Format | Result | Pagination and splitting |
| --- | --- | --- |
| SVG | Deterministic vector score output with an opaque page background, white by default. Downloaded SVG embeds needed ornament glyphs. | A paginated export is one combined SVG by default. Browser or CLI Split pages produces one SVG per page. CLI split output uses the `-o` value as a stem and refuses to overwrite a target. |
| PNG | Opaque raster image of the same SVG layout, using bundled export fonts and a configurable pixel scale. | Browser and CLI support one PNG per page when Split pages is enabled. |
| PDF | Vector PDF pages with Unicode text and ornament fonts embedded. | Each rendered page becomes one PDF page. PDF is not split into separate downloads. |

Browser downloads use the current Page and Export Settings. CLI commands put equivalent choices beside the command: `--paper`, `--orientation`, `--page-width`, `--page-height`, `--page-margin`, `--page-footer`, `--page-numbers`, `--paginate`, `--color`, and `--background`. Color and background accept `#RRGGBB` only. PNG additionally accepts `--png-scale`; SVG and PNG accept `--split-pages`. The browser and CLI report the same layout-warning categories for horizontal scaling, overheight groups, very small usable page height, and excessive page counts; CLI visual exports still succeed when only these warnings are present.
